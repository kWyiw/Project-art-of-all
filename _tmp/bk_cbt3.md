## 第 1 章 总则

**BT-1.1　战斗是自动战斗。**
战斗开始后，双方玩家都没有任何操作权。没有技能按钮、没有暂停、没有取消。战斗一旦开始，只能看它打完。

**BT-1.2　战斗以 tick 计时。**
60 tick = 1 秒。所有冷却、状态周期、持续时间都必须是**整数 tick**。战斗内不出现"秒"这种单位。

| 现实时间 | tick | 含义 |
|---|---|---|
| 0.5 s | 30 | 灼烧结算间隔 |
| 1 s | 60 | 中毒/再生结算间隔 |
| 3 s | 180 | 常见冷却 |
| **20 s** | **1200** | **超时惩罚开始** |
| 25 s | 1500 | （参考） |
| **60 s** | **3600** | **判平局（硬上限）** |

**BT-1.3　战斗是纯函数。**
一场战斗的全部输入 = 左方阵容 + 右方阵容 + 双方按等级查到的**最大生命值** + 一个随机种子。同样的输入必然产出完全相同的结果，一个字节都不差。
因此战斗**不可中断、不可回滚、不可预测**——这三条是免费的，因为战斗期玩家零输入。

**BT-1.4　双方信息半公开。**
分成 战斗外阶段 战前准备阶段 战斗中阶段 ，战斗外阶段双方都看得见对方的战斗栏。战前准备阶段看不见对方的战斗栏，战斗中阶段双方都看得见对方的战斗栏。这样玩家可以在战斗外阶段搜集对手的情报，在战前准备阶段摆出针对对手的阵容。

## 第 2 章 战场

**BT-2.1　一对一。**
一场战斗只有两个单位：左方与右方。多次战斗之间**没有任何继承**——生命、护盾、状态、CD 全部重来（BT-5.1）。

**BT-2.2　每方一个战斗栏。**
战斗栏是一维序列，有顺序、有左右、宽度受限。宽度与摆放规则见 `卡牌构筑规则书` CJ-5。**战斗栏的顺序决定"相邻"与"从左到右的触发顺序"**，这两件事都影响胜负。

**BT-2.3　阵容在两阶段后锁定：准备期 → 开战瞬间。**
战斗的"开始"不是一个瞬间，而是**准备期（5 秒）+ 开战瞬间**两段。准备期内阵容仍可调，开战瞬间锁定；锁定后，任何外部变化（商店刷新、卖牌、断线重连）都不影响这一场战斗。断线重连只能重放出同一个结果。

**BT-2.3.1　准备期固定 5.0 秒（300 tick @60Hz），从"战斗已确定发生"那一刻起算。**
"战斗已确定发生"= 发起方落点结算完毕、双方身份与奖惩基数都已确定（`大富翁层规则书` §2.3）。准备期内**战斗尚未开始**：生命值未填满、CD 未就绪、`战斗开始时`效果一律未触发（它们在 BT-2.5 才执行）。

**BT-2.3.2　准备期内参战方可以自由调整战斗栏。**
允许：战斗栏内重排、从背包把牌拖进战斗栏、把战斗栏的牌拖回背包、出售卡牌。受 CJ-5 宽度与 CJ-5.2 解锁等级约束。

**BT-2.3.3　准备期内允许出售，但只限"改变牌组内容"的出售。**
允许：出售卡牌（免费、不限次，CJ-6.5）。出售时效果照常结算（R-ECO-014），计入发起方本回合。
不允许：购买、主动使用卡牌效果、打开商店。这三件事只在棋盘层做——否则 5 秒准备期会变成"临场刷牌"，
把"调整阵容"变成"二次构筑"。

**BT-2.3.4　准备期内的信息隔离：双方互相看不见对方的战斗栏。**
- PvP：双方各自看到自己的战斗栏 + 棋盘暗化 + 倒计时；**看不到对手任何牌**（连牌名都不给）。
- PvE：玩家看自己的战斗栏 + 对手单位的公开信息（名字、生命上限），看不到它的"阵容"（怪物阵容由模板固定，本来也不变）。
- 未参战的第三方玩家：只看到 `P1 vs P2 · 准备中`，同样看不到牌。

**BT-2.3.5　提前开始与超时。**
- 每个参战方有独立的「准备完毕」按钮。**所有参战方都点过 → 立即开战**（不浪费剩余秒数）。
- 5.0 秒到 → 未点的一方自动视为准备完毕，直接开战。
- **PvE 只有玩家一个参战方**，所以点一次「立即开战」即可跳过准备期（默认习惯：连打杂鱼不点也行，5 秒自动过）。

**BT-2.3.6　准备期不计入战斗时长。**
超时惩罚的 1200 tick（BT-9.3）从 **BT-2.5 初始化完成后的第 1 个 tick** 开始计，准备期不占这 20 秒。这条必须写死：否则"5 秒准备 + 15 秒战斗"会被玩家读成"这局打了 20 秒"，且平局线（60 秒）的体感会错。

**BT-2.3.7　准备期内的排列变更仍是权威命令。**
每次松手发 `ReorderCommand`（见 UI 规格 §7.2），服务器接受才算数；开战瞬间以**服务器最后一次接受的排列**为准。客户端本地已拖但未确认的改动在开战时丢弃。

> **为什么给 5 秒而不是 0 秒**：PvP 的发起方是主动方，被挑战方是被动方。若准备期为 0，"立刻开打"会让被挑战方永远用着上一次随手摆的阵容——这不是技巧差距，是信息与时间的不对称。5 秒刚好够"我把它挪到隔壁"这一个动作，不够重新构筑，所以不会让战斗变成临时拼装比赛。

---

**BT-2.4　生命值在开战瞬间按等级填满，战斗中只减不增（除治疗）。**
生命值**不属于棋盘层**（BT-4.7）。每场战斗开始时，双方生命都 = 自己等级对应的生命上限，从满血开打：

| 等级 | 1 | 2 | 3 | 4 | 5 |
|---|---|---|---|---|---|
| 生命上限 | 100 | 150 | 200 | 250 | 300 |

（该表**已确认**为正式数值。6 级 = 胜利，因此不存在 6 级的战斗生命。）

**这意味着"上一场打得只剩一丝血"不会影响这一场**——没有残血惩罚，也就没有"打完架必须在 home 养伤"这种隐性停摆。

**BT-2.5　战斗开始时的初始化（必须按此顺序执行一次）**

```
① 生命值 = 该玩家等级对应的上限（满血开战，BT-2.4）
② 清空双方所有状态：中毒 / 灼烧 / 再生 / 护盾 全部归零（护盾本来就是 0，但流程上必须显式清）
③ 所有卡牌的冷却置为「就绪」（CD = 0）
④ 所有战斗内（BattleScope）修正清空，局内（RunScope）修正作为基础值载入
⑤ 触发「战斗开始时」类效果（如粉碎机的摧毁废料）
⑥ 开始 tick 循环
```

> **为什么冷却从"就绪"开始**：如果从满冷却开始，短 CD 的牌会因为"冷启动"白赚一轮，而长 CD 的牌一开始就吃亏。从就绪开始对双方对称，且战斗开局有爆发感。
> **为什么初始化要写死顺序**：第 ⑤ 步的"战斗开始时"效果可能改变阵容（摧毁卡牌），必须在 tick 循环之前一次性结算完，否则会和第 1 个 tick 的触发抢顺序。

**BT-2.6　战斗中有"回合"吗？没有。**
战斗内只存在 tick。任何卡牌文字里出现"每回合结束"，指的是**棋盘层的回合**，战斗内不触发。战斗中生成卡牌同理——见 CJ-7。

## 第 3 章 时间推进

### 3.1 每个 tick 的固定五步

**BT-3.1　每个 tick 严格按以下顺序结算。顺序不得调换、不得并行。**

```
第 ① 步  推进所有卡牌的冷却
第 ② 步  结算周期性状态（中毒 → 灼烧 → 再生）
第 ③ 步  触发所有「冷却归零」的卡牌
第 ④ 步  结算护盾吸收与治疗，判定击倒
第 ⑤ 步  结算超时惩罚（1200 tick 起每 6 tick 一次，见 BT-9.3），结算后**再次判定击倒**；检查 3600 tick 平局
```

> **这个顺序是硬规则，不是实现细节。** `①→③` 和 `③→①` 会让"冷却恰好在本 tick 归零"的牌在一场战斗里多打或少打一次。20 秒里，3s 的牌本该打 7 次（t=0,3,…,18），多一次就是 14% 的差距。**必须进自动化测试。**

### 3.2 冷却推进

**BT-3.2　每张牌每 tick 推进 1 个 tick 的冷却**，再乘速度倍率。

**BT-3.3　速度倍率用整数分数表示，整个系统只有三种取值。**

```
速度 = 1/1    无修饰
速度 = 2/1    有加速
速度 = 1/2    有缓速
速度 = 1/1    加速与缓速同时存在（互相抵消）
```

因为效果不叠加（BT-3.4），倍率**永远只在这三种之间切换**，不会出现 ×4、×1/4、×1/8。

实现上用整数累加器，避免浮点：

```
每 tick：acc += 速度分子
         当 acc >= 速度分母 时：acc -= 速度分母；cdRemaining -= 1
```

例：一张 3s（180 tick）的牌被施加缓速 → 每 tick 推进半格 → 实际需要 360 tick（6 秒）才能就绪。

**BT-3.4　加速 / 缓速只叠加持续时间，不叠加效果。**

| 项 | 规则 |
|---|---|
| 效果强度 | **固定**。加速恒为 ×2，缓速恒为 ×1/2。永远不会变成 ×4 或 ×1/4 |
| 叠加方式 | 对同一张牌重复施加同一种修饰 → **剩余时间相加**，效果仍为 1 层 |
| 加速 + 缓速 同时存在 | 两者相乘 → ×2 × 1/2 = **×1**，互相抵消（时间各自独立计时） |
| 层数上限 | 无上限（因为效果不叠加，堵多少层结果都一样） |

例：

```
一张 3s 的牌先被缓速 2s，再被缓速 1s
→ 缓速剩余时间 = 3s，速度倍率仍为 ×1/2
→ 就绪时间 = 180 × 2 = 360 tick，但不只 3s 有效——是连续 3 秒都在 ×1/2
```

**BT-3.4.1　重复施加时，剩余时间取"相加"，不管来源。**
塑料棚在一次施法里对同一张牌产生 3 次缓速事件 → 结果不是 3 层，而是"缓速 6 秒"。

> **这条规则让"缓速流"变成一种节奏压制，而不是一张删牌。**
> 效果不叠加意味着：一张牌最慢也就 ×1/2——3 秒的牌变 6 秒，还算能打；12 秒的牌变 24 秒，一局只出 2 次。而**时间可以无限累加**，所以不停施加缓速能把一张牌长期压在半速，这才是有意义的控制：靠持续投入换持续压制，而不是靠一次叠满直接删掉。

**BT-3.5　加速 / 缓速有剩余时间，到期自动移除。**
到期在 tick 的**第 ① 步之前**结算。剩余时间归零的那一刻，倍率立刻恢复。若加速与缓速同时存在，其中一方过期后，倍率立即从 ×1 变回另一方生效的 ×2 或 ×1/2。

### 3.3 充能

**BT-3.6　充能 N 秒 = 目标牌的剩余冷却立即减少 60×N tick，最低减到 0。**
充能不会让 CD 变成负数；超出当前剩余冷却的部分记为这张牌的 `chargeCarry`（tick），
在该牌**下一次进入冷却**时从新 CD 里直接扣掉，扣到 0 为止、多出的部分丢弃。
`chargeCarry` 不跨战斗：战斗结束即清零（与 BT-4.7 的"战斗内状态"同一生命周期）。

### 3.4 多重释放

**BT-3.7　多重释放 N = 本次施法完整重复 N+1 次。**

**BT-3.8　重复不额外消耗冷却。** 一次冷却换 N+1 次效果。

**BT-3.9　每一次重复都是一次完整施法**，会完整地产生事件、触发自身与全场的被动。这与"这一行效果多写了几遍"不同。

> **这条为什么重要**：塑料棚写的是"缓速对方 3 张牌 2 秒（视作触发 3 次缓速）"。如果实现成"一次事件带 3 个目标"，它自己的被动只会触发 1 次护盾；实现成 3 次独立施法才对。同理，火堆的 3 连释放会 3 次触发"每次造成灼烧"类的被动。

### 3.5 触发顺序

**BT-3.10　同一 tick 内，同一方的多张牌就绪时，按战斗栏从左到右依次施法。**

**BT-3.11　同一 tick 内，双方都完整结算完自己的施法，然后才统一判定击倒。**
不存在"左方先打所以赢"的先手优势。

> **这条是公平性的核心。** 如果按"谁先结算谁先赢"，那么战斗栏靠左的牌、或者左方单位，会系统性占优。BT-3.11 消除它：本 tick 双方的伤害都算完，再一起看谁死了。如果双方都在本 tick 归零，判**平局**（BT-10.2）。

## 第 4 章 伤害与护盾

**BT-4.1　伤害值 = 骰值 + 修正，然后 clamp。**
每一枚骰子**独立**取骰值、独立加修正、独立 clamp 到 `[1, 骰面上限]`，最后求和。

例：`1D6 + 2`，投出 3 → 3+2 = 5。投出 6 → 6+2 = 8，但 clamp 到 6，所以是 6。

**BT-4.2　clamp 的下限是 1，不是 0。**
`1D6 - 3` 投出 1 → -2，clamp 到 1。

**BT-4.3　护盾优先吸收伤害。**
有护盾时，伤害先扣护盾，护盾不够的部分才扣生命。

**BT-4.4　"无视护盾"的伤害直接扣生命。**
中毒是目前唯一无视护盾的伤害来源（BT-6.2）。**超时惩罚不属于这一类**——它会被护盾吸收（BT-9.3）。

**BT-4.5　护盾没有上限，但只在本场战斗内存在。**
护盾可以累积到超过最大生命值，不封顶、不衰减、战斗内不清零。**战斗一结束，护盾不是"归零"，而是整个消失**——它不进入棋盘层、不带进下一场战斗、不因为卖牌或升级而保留（BT-5.1）。

> **为什么不封顶**：因为护盾的生命周期被锁死在一场战斗之内，且战斗一定有终点（BT-9.3 超时惩罚 / BT-9.4 60 秒硬平局）。堆到 300 的护盾也只是"这一场更难死"，不会滚成永久资产。**用生命周期兜底，比用数值封顶干净**，同时完整保住"纯防御流"这个玩法空间。

**BT-4.6　护盾与超时惩罚的关系：被打穿，不被绕过。**
超时惩罚是**普通伤害**，走的还是 BT-4.3 的顺序：先扣护盾、护盾不够才扣生命。这意味着：

| 谁活得久 | 原因 |
|---|---|
| 有效生命（生命 + 护盾）更高的一方 | 惩罚对双方等量，是一场"谁的血池更深"的赛跑 |

**这就是"只叠盾、不打人、靠超时惩罚耗死对手"这套玩法成立的规则基础**，它是被明确允许的构筑路线，不是漏洞。反制手段是中毒（BT-5.3，唯一无视护盾的伤害）和"在 20 秒前把对方打死"。**60 秒硬平局（BT-9.4）保证两个纯盾 build 不会无限拖。**

**BT-4.7　生命值只存在于战斗之内。**
棋盘层没有生命值——玩家在棋盘上永远是满状态，不存在"残血走棋盘"。所以：生命上限是**由等级决定的战斗内参数**（见 `大富翁层规则书.md` §2.2），棋盘层的地块、事件、卡牌都不读也不写生命。

> **这条是很多设计文档最容易混的一处**：一旦棋盘层存在生命值，就必然要引入"回血地块""复活""残血惩罚"一整串系统。你的游戏不需要，就不要留这个口子。

**BT-4.8　生命下限 0，上限 = 最大生命。**
治疗不会超过最大生命。生命恰好为 0 即被击倒。

**BT-4.9　"累计造成伤害"独立记录（仅作统计，不参与裁决）。**
本场战斗里，每个单位累计打出的**原始伤害数值**（不扣护盾吸收、不算治疗）单独记账，用于战后战报与 BalanceSim。中毒、灼烧的伤害计入；**超时惩罚伤害不计入**（它不属于任何一方）。

## 第 5 章 状态效果

**BT-5.1　战斗状态共 5 类，全部在战斗结束时清零，不跨战斗。**
中毒、灼烧、再生、护盾、速度修饰（加速/缓速）。

**BT-5.2　层数恒为整数。**
骰值本身就是整数。层数的加减一律用整数运算，禁止浮点——唯一会做减法的状态是灼烧（每次 −1 层），它也不涉及除法。

### 5.1 中毒

**BT-5.3　中毒每秒造成（层数）点伤害，无视护盾。**
在 tick 的第 ② 步结算，每秒一次（每 60 tick）。

**BT-5.4　中毒层数不衰减。施放即累加，层数只增不减，直到战斗结束时统一清零。**

```
每次施法： 层数 += 骰值（1D4，取值 1~4）
每秒结算： 造成「当前层数」点伤害，层数不变
```

例：核废水（1c，4s CD，1D4）在 25 秒内施放 7 次：

| 时刻 | 本次 +层 | 累计层数 | 本秒伤害 |
|---|---|---|---|
| 0 s | 2 | 2 | 2 |
| 4 s | 2 | 4 | 4 |
| 8 s | 3 | 7 | 7 |
| 12 s | 2 | 9 | 9 |
| 16 s | 3 | 12 | 12 |
| 20 s | 2 | 14 | 14 |
| 24 s | 2 | 16 | 16 |

**这就是中毒的设计定位：伤害随时间**线性增长**的延迟投资。**
一张 1c 的核废水在 25 秒内的累计伤害约为 **165~195**（视骰运），是撬棍（约 29）的 5~6 倍。这是有意保留的强度，不是 bug——它换来的是"**前 10 秒几乎没威胁**"。

> **为什么这个特性值得保留**：中毒是唯一一张"投入越早越强、且必须在早期承担风险"的牌。它让棋盘层产生一个真实的策略压力——发现自己身上有中毒的玩家必须抢快攻，而带中毒的人必须熬过前 10 秒。这个张力是撬棍这类稳定输出给不了的。
>
> **留了一个旋钮，但本版不启用**：如果实测下来中毒确实压倒其他牌，最小改动的修法是给它加"每层存活 8 秒"的**持续时间**（初稿没有写，本版不引入），而**不是加衰减**——持续时间的改法保住了"层数只增不减"的规则形状，只是让旧层过期。**改一个数就行，不动规则结构。**

### 5.2 灼烧

**BT-5.5　灼烧每 0.5 秒造成（层数）点伤害，然后层数 −1。**
在 tick 的第 ② 步结算，每 30 tick 一次。层数降到 0 时移除。

> **灼烧为什么不需要额外规则**：它自带"每次结算 −1 层"的自我限制，最多只能堆到"层数 = 每次收益 / 每秒结算次数"。火堆配 2 张相邻废料，累计约 32 点/8 秒 ≈ 4 dmg/s，是健康的持续输出。**灼烧是自限状态，中毒是无上限状态，两者强度曲线形状不同，这是设计上的分工，不是不平衡。**

### 5.3 再生

**BT-5.6　再生每秒恢复（层数）点生命。层数不衰减，施放即累加，直到战斗结束清零。**
恢复不超过最大生命。结算顺序与中毒相同（tick 第 ② 步，每秒一次）。

> **再生是"负中毒"，规则完全对称**：层数只增不减，秒治疗量随时间线性爬升。
> 一张 1c 的压缩饼干（3s CD，1D4）在 25 秒内提供约 **240~280** 点治疗——**超过任何等级的最大生命值**。也就是说，只要没人能在前 10 秒把它打死，这张牌独自就能把对手的全部输出磨平。
> 这是它的设计定位（治疗型构筑的终局答案），代价同样是前期极脆。BalanceSim 跑批时把它作为重点观测项。

### 5.4 护盾

**BT-5.7　护盾是一个数值池，被伤害消耗。**
它不按 tick 结算，只在第 ④ 步按 BT-4.3 吸收。**没有上限**（BT-4.5）。

### 5.5 速度修饰

**BT-5.8　加速/缓速以"剩余 tick + 倍率"的形式挂在**单张牌**上，不是挂在单位上。**
详见 BT-3.3、BT-3.4、BT-3.5。

**BT-5.9　充能是即时效果，但溢出量会留在这张牌上。**
充能本身不占状态栏、不因"被清除状态"而失效；唯一被保留下来的是 BT-3.6 的 `chargeCarry`——
它属于这张牌的**冷却数据**，不是"状态"，因此不被"清除状态"类效果影响，只被"重置该牌冷却"类效果清掉。

## 第 6 章 数值修正

**BT-6.1　修正只作用于骰值，不作用于"数量"。**

| 是"骰值" | 是"数量" |
|---|---|
| 1D6 的骰值 | 多重释放的 N |
| 1d20 的骰值 | 目标数量（"缓速 2 张牌"） |
| `X d4` 里的每一枚骰 | `X`（价值）本身 |
| 充能/加速的秒数 | 持续的秒数 |

> **这条必须分清**：磨刀石写"相邻武器伤害值 +2 修正"，它加的是骰值。如果一个效果写"多重释放 +1"，那不是修正，它不受 clamp 影响，也不会被"骰面上限"限制。

**BT-6.2　修正的作用域只有三种，每一处修正都必须能明确归到其中一种。**

| 作用域 | 生命周期 | 例 |
|---|---|---|
| 单次结算（Tick） | 本次施法内 | — |
| 本场战斗（Battle） | 战斗结束时清空 | 热熔切割器"每次缓速使骰数+1" |
| 本局（Run） | 写存档，跨战斗保留 | 粉碎机"永久+1"、幸运饼干的永久修正 |

**BT-6.3　修正的来源相加后**一次性** clamp。**
`最终值 = clamp(骰值 + 卡牌自身修正 + 全部光环修正 + 局内永久修正, 1, 面数)`

**BT-6.4　局内永久修正在进入战斗时作为"基础修正"载入**，它在战斗内不能再被清除。

## 第 7 章 光环与相邻

**BT-7.1　光环每次求值时都重新计算，绝不在装备时固化。**

> 火堆的"每与一张废料相邻就 +1 多重释放"会随相邻牌变化，自噬之蛇的加成会随重排变化。如果固化，"重排战斗栏"这个操作就会产生歧义（我排好之后再排回去，加成还在吗？）。**动态求值让这个问题不存在。**

**BT-7.2　求值公式**

```
最终骰值 = clamp( 骰值 + Σ(所有生效修正) , 1 , 骰面数 )
最终数量 = 基础数量 + Σ(所有生效的数量加成)     // 不受 clamp
```

**BT-7.3　光环之间不允许形成循环依赖。**
"A 加强 B、B 又加强 A"这种结构必须在**数据加载阶段**被检测并拒绝，不能等到战斗中才发现。

> 这不是洁癖。允许光环链之后，玩家一定会拼出 A→B→C→B，然后要么数值爆炸，要么求值死循环。**在加载器里做一次有向图环检测，把环当作加载错误直接拒绝**，是最省事的做法。

**BT-7.4　相邻的定义**

| 选择器 | 含义 |
|---|---|
| 自身 | 这张牌 |
| 左邻 | 战斗栏里紧挨在左边的**1 张** |
| 右邻 | 紧挨在右边的**1 张** |
| 全部相邻 | 左邻 + 右邻（最多 2 张） |
| 按词条筛选 | 满足条件的全部牌，或"相邻范围内满足条件的牌" |

**BT-7.5　已被摧毁的牌不参与任何求值。**
不算相邻、不提供光环、不算"废料的邻居"、不算"最左侧的牌"。

> **这条极易写错**：粉碎机摧毁废料之后，如果被摧毁的废料仍然算"火堆的邻居"，那"摧毁废料"反而会强化火堆。**摧毁 = 从序列里消失**，包括所有求值。

**BT-7.6　"最左侧""最右侧"按当前战斗栏求。**
若序列为空则该效果静默失效，不报错、不占位。

**BT-7.7　取最大骰不是"修正 +100"（自噬之蛇裁决）。**
自噬之蛇的效果**不通过修正系统实现**，而是一个独立的、优先级最高的"骰值覆盖"：

```
若存在 MaxRoll 覆盖：
   最终骰值 = 骰面数        // 直接取满，不参与 clamp 前的求和
否则：
   最终骰值 = clamp(骰值 + Σ修正, 1, 骰面数)
```

**BT-7.7.1** 必须做成独立的骰值覆盖，**不能表达成"修正 +N"**：修正会渲染到卡面与 tooltip（`★+N`），玩家读到的是"加了多少点"而不是"必定满骰"——**文案与实际效果的偏差会在联机争议时变成规则漏洞**（"我以为是加 100 所以应该溢出"）。
**BT-7.7.2** 卡面文案统一写：`右侧相邻牌的所有骰值必定取最大值`。
**BT-7.7.3** `MaxRoll` 与 `修正` 同时存在时，**MaxRoll 优先**，修正不再计入（避免"负数修正 + MaxRoll"的歧义）。
**BT-7.7.4** 对 `Xd6` 这类多骰，**每一颗骰都取满**——它加强的是"所有骰值"，不是"总值"。

## 第 8 章 摧毁与禁用

**BT-8.1　"摧毁"默认是本场战斗内的临时移除。**

```
被摧毁的牌：
  ✗ 不再触发
  ✗ 不再提供光环
  ✗ 不再被算进相邻
  ✗ 不再被算进"最左侧/最右侧"
  ✓ 槽位空出
  ✓ 战斗结束后完全恢复
```

**BT-8.2　例外：显式写明"永久"的摧毁是局内移除。**
当前只有一张：**粉碎机**——"摧毁背包最左侧的废料，使这张牌的掷骰数永久+1"。

> ⚠️ **这是原卡面文字里的一处漏洞，必须按本条规定裁决。**
> 如果按 BT-8.1 的默认（战斗内临时摧毁），废料在战斗结束后会回来，而 +1 骰数是永久的 —— 于是玩家每打一场就白赚 +1 骰数、零代价，可以无限刷。
> **裁决：粉碎机的摧毁是永久摧毁（局内），被摧毁的废料不会回来。** 这是它"用一张废料换一次永久成长"的设计意图。

**BT-8.3　战斗内被摧毁的牌，战斗结束后回到背包，不带任何惩罚。**
否则玩家会因为"打一场少两张牌"而不敢进战斗，整个节奏就崩了。

## 第 9 章 战斗结束

**BT-9.1　一方生命归零，战斗立即结束。**

**BT-9.2　同一 tick 内双方同时归零 → 平局。**
平局时双方碎片不变、胜场不变。

**BT-9.3　超时惩罚：20 秒起双方持续受到递增的伤害。**
这是战斗唯一的强制终止机制。它不判定胜负，只是**逼**战斗结束。

> **注意：惩罚不是"真实伤害"，它会被护盾吸收（BT-4.6）。** 这是玩家的明确裁决——它让"只叠盾、不打人、靠超时惩罚耗死对手"成为一条合法的构筑路线。

**BT-9.3.1　起点与节奏**

| 项 | 值 |
|---|---|
| 惩罚开始 | 1200 tick（20 秒） |
| 结算间隔 | 6 tick（0.1 秒） |
| 作用对象 | **双方同时**，各自独立承受 |
| 伤害类型 | **普通伤害**：先扣护盾（BT-4.3），护盾不足才扣生命；**不受任何修正、不被减免、不可闪避、不触发"受击"类被动** |
| 是否计入「累计造成伤害」 | **否**（它不属于任何一方打出的伤害） |

**BT-9.3.2　伤害公式（整数，无浮点）**

```
k = 超时后第几次结算（k = 1, 2, 3, …）
本次伤害 = (k + 9) / 10        // 整数除法，等价于 ceil(k / 10)
```

即：**每过 1 秒，每次结算的伤害 +1**。伤害随超时时间线性增长，累计是平方增长。

| 超时时间 | k | 单次伤害 | 该秒合计 | **累计** |
|---|---|---|---|---|
| 0.1 s | 1 | 1 | — | 1 |
| 1 s | 10 | 1 | 10 | 10 |
| 2 s | 20 | 2 | 20 | 30 |
| 3 s | 30 | 3 | 30 | 60 |
| 5 s | 50 | 5 | 50 | 150 |
| 6 s | 60 | 6 | 60 | 210 |
| 10 s | 100 | 10 | 100 | 550 |

**BT-9.3.3　实际效果**

| 有效生命（生命 + 护盾） | 累计伤害攒够所需 | 大约在超时第几秒被惩罚打死 |
|---|---|---|
| 300 | 300 | 7~8 s（即 t ≈ 27~28 s） |
| 400 | 400 | 8~9 s（t ≈ 28~29 s） |
| 600 | 600 | 10~11 s（t ≈ 30~31 s） |
| 1000 | 1000 | 13~14 s（t ≈ 33~34 s） |

（累计伤害公式：超时 s 秒后 = `5s² + 5s`）

**所以绝大多数战斗会在 20~28 秒之间结束**；纯盾流能把它拖到 30 秒出头，拖不到 60 秒。

> **这组数字就是"叠盾耗死对手"玩法的强度标尺**：有效生命每多 100，大约多活 0.7~1 秒，而且边际递减。所以纯盾流的胜利条件是**比对方晚死**，不是把对方打死——惩罚伤害对双方等量（BT-9.3.1），有效生命更高的一方自然最后倒下。这在规则上完全成立，是明确允许的构筑路线。

**BT-9.4　60 秒硬上限：判平局。**
到 3600 tick（60 秒）时，无论双方生命多少，**战斗立即结束，判双方平局，不进行任何战胜/战败的资源流动**（碎片不转移、胜场不增加、不位移、不升级判定）。

> **这条的意义**：它是兜底。按 BT-9.3 的成长曲线，正常配比下根本打不到 60 秒——能撑到 60 秒的只有"双方都是超高再生、互相抵消超时伤害"的极端局面。**规则的存在不是为了被触发，是为了让极端局面一定收敛。**
> 同时它明确了平局的经济含义：**平局 = 没有赢家 = 没有资源流动**。这比"平局按血量分账"干净，也堵掉了"故意拖到 60 秒来避免战败损失"的动机——因为你照样赢不了。

**BT-9.5　战斗结束的瞬间，不再结算任何触发。**
包括"本 tick 已经排好但还没执行的触发"。

**BT-9.6　战斗结果必须包含以下字段，交给棋盘层。**

| 字段 | 说明 |
|---|---|
| 胜负方 | 左 / 右 / 平 |
| 结束原因 | 击倒 / 超时惩罚击倒 / 60 秒平局 |
| 结束 tick | 便于统计战斗时长分布 |
| 是否进入超时惩罚 | 用于平衡统计 |
| 双方剩余生命 | **只用于战报与复盘**。棋盘层没有生命值，不回写任何状态（BT-4.7） |
| 双方累计造成伤害 | 复盘用（不含超时惩罚） |
| 双方最终上场牌 | 含被摧毁的牌及其恢复清单 |
| 完整事件流 | 用于回放与调试 |

## 第 10 章 表现与日志契约

**BT-10.1　战斗必须能在 1/8 时间（约 3 秒）无损重放。**
因为结果是预先算完的纯函数，"加速播放"只是把事件流按更快的时间轴染色，**不重新模拟**。这也意味着：加速播放的结果与正常播放**逐字节一致**。

**BT-10.2　战斗日志至少要能回答这 4 个问题：**

1. 我为什么输了？（哪张牌打出了多少伤害）
2. 对方哪张牌最强？（按造成的总伤害排序）
3. 我的哪张牌没起作用？（出手次数为 0 或效果被完全吸收）
4. 下次该换掉什么？（给出"每槽有效输出"这一列）

**BT-10.3　"随机选目标但候选集为空"必须有一行灰字提示。**
例如"（无可作用目标）"。否则玩家会认为卡了。

## 第 11 章 易错点清单（Top 13）

按"最容易写错"排序。每一条都建议配一个单测。

| # | 易错点 | 正确做法 |
|---|---|---|
| 1 | tick 内顺序写成 ③→① | 必须 ①推CD → ②状态 → ③触发 → ④吸盾判死 → ⑤超时惩罚+再判死 |
| 2 | 谁先结算谁先赢 | 同 tick 双方都算完再判死；同时归零判平局 |
| 3 | 摧毁的牌还参与相邻 | 摧毁 = 从序列消失，不参与任何求值 |
| 4 | 修正加在总和上 | 修正加在**每一枚骰子**上，逐枚 clamp |
| 5 | 修正当成了数量加 | 多重释放、目标数、秒数都不受修正影响 |
| 6 | 价值被 clamp | 价值是"数量"，可以超过骰面 |
| 7 | 光环在装备时固化 | 每次求值都重算 |
| 8 | 加速/缓速按层数叠加效果 | **只叠时间**：效果恒为 ×2 / ×1/2，重复施加延长剩余时间（BT-3.4） |
| 9 | 给中毒/再生擅自加了衰减或层数上限 | 层数只增不减，只在战斗结束时清零（BT-5.4 / BT-5.6） |
| 10 | 给护盾加上了上限 | **护盾不封顶**（BT-4.5），但只在本场战斗内存在，且 60 秒硬平局兜底 |
| 11 | 把超时惩罚做成"无视护盾的真实伤害" | 它是**普通伤害**，被护盾吸收（BT-4.6）；但**不计入**累计造成伤害 |
| 12 | 让生命值或护盾跨出战斗 | 棋盘层没有生命值（BT-4.7）；护盾战斗结束即消失（BT-4.5） |
| 13 | 粉碎机摧毁不永久 | 必须永久，否则无限白嫖成长 |

## 附录 C　与棋盘层的接口清单

| 时机 | 方向 | 内容 |
|---|---|---|
| 开战前 | 棋盘 → 战斗 | **双方按等级查到的最大的生命值**（不是"当前生命"，棋盘层没有生命值，BT-4.7）、双方战斗栏快照、种子 |
| 开战前 | 棋盘 → 战斗 | 局内永久修正（BT-6.4 的基础值） |
| 战斗中 | — | 无交互（BT-1.3） |
| 战斗后 | 战斗 → 棋盘 | 胜负、结束原因（击倒 / 超时 / 60 秒平局）、被摧毁但需恢复的牌、永久摧毁的牌 |
| 战斗后 | 棋盘层结算 | 碎片与胜场转移、升级判定——**全部在棋盘层做**。战败**不产生位移**（R-CBT-005，v1.6） |

> **战斗层不写任何棋盘状态，棋盘层也拿不到生命和护盾。** 它只返回一个结果对象。这条纪律是"战斗可纯函数化"的唯一保障。
