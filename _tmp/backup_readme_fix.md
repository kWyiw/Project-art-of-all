# 规则书 · 文档索引

> 后续我会再修改。
> 这个目录只有一件事：把设计稿变成可编码的规则与规格。

> **项目形态（v1.7 定调）**：**4 人派对游戏**。阶段 A 先做单机 = 1 真人 + 3 CPU；阶段 B 再做联机 = 4 真人。
> **两种模式规则完全一致**：同一份内核、同一套命令、同一张地图、同一个卡池。差别只有"那 3 个席位由谁填"和"命令过不过网络"。
> 因此这套文档里**没有"单机专属规则"**——任何时候想给单机单开一条规则，先假设它会让 M6 的成本翻倍。


一句话记法：**规则书说"能不能"，规格书说"怎么实现"，UI 规格说"手怎么动"。三者冲突时，前者压后者。**

## 5. 文档维护规则

1. **一条裁决只在一个地方定义**，其它文档用编号引用（如 `BT-9.3`），不复制正文。复制正文必然分叉。
2. **改规则 = 改编号条目 + 检查交叉引用**。改完 `R-CBT-005` 就要搜一遍 `R-CBT-005` 的所有引用点（`战斗规则书.md`、`战斗与卡牌系统规格书.md` §12、测试用例表）。
3. **"已裁决"必须写进规则书，不能只留在对话里**。规格书 §14 是裁决索引，新增裁决先加一行，再落到具体编号。
4. **删除机制要把三处一起改**：规则条目、理由段、测试用例。删"战败返回 home"时就同步改了 `R-CBT-005`、`R-HOME-007`、测试表两行、规格书 §12——漏任何一处都会留下自相矛盾的文档。
5. **版本号只增不改历史**：文档头只保留当前版本号与一句"本册管什么"，不堆叠 changelog。被删机制不留墓碑。
