# 大富翁层规则书 v1.7

> **本册管什么**：棋盘层——拓扑、移动、停留、地块、经济、升级、胜负、回合结构。规则编号 `R-<域>-<序号>`，代码注释与测试用例均引用编号。
> **不管什么**：战斗内部（`战斗规则书.md`）、卡牌与摆放（`卡牌构筑规则书.md`）、卡槽拖拽（`棋盘层双栏卡槽UI与拖拽交互规格.md`）、工程实现（`战斗与卡牌系统规格书.md`）。
> **项目形态**：四人派对游戏，规则一律按 4 名玩家书写。阶段 A = 1 真人 + 3 CPU，阶段 B = 4 真人；两种模式的规则、数值、地图、卡池完全一致，差异只在"席位由谁填、命令从哪来"。因此本文不存在"单机专属规则"。

### 1.2 地图

```
R-MAP-001  地图是**有向图**：节点 + 有向边。只能沿出边前进，不可逆行。
R-MAP-002  节点出边数 = 2 及以上，且被标记为 forkNode 时，该节点是岔路。
R-MAP-003  地图数据须通过 4 项校验：
           ① 每个节点至少 1 条出边
           ② 从任一 spawn 可达全部节点

           ④ 传送组至少 2 个成员，且组内互不为同一节点
R-MAP-004  表现坐标（pos）只供渲染，逻辑层禁止读取。
R-MAP-005  每个玩家出生在其 HomeTile 上。
R-MAP-006  地块 = 基础地块（恒为 Base）+ 0..n 个地块效果（TileEffect）。

### 1.3 回合阶段

```
R-TURN-001  回合顺序按玩家序号 0→1→2→3 循环。
R-TURN-002  一个回合只有一个主动操作： MOVE（必须）。
            其余一切对栏位中卡牌的处理（移动/出售）为免费动作，不消耗回合。
R-TURN-003  MOVE 阶段结束后结算地块效果，然后进入 TurnEnd。
R-TURN-004  TurnEnd 触发：行动后收益类效果 → 写存档点 → 切换玩家。

### 1.4 移动（核心算法）

```
R-MOVE-001  掷骰：1D6，值 1~6。
R-MOVE-002  移动从当前节点出发，沿出边前进 k 步（k = 骰子点数）。
R-MOVE-003  【经过】= 中间节点；【停留】= 终点或主动选择的停下点。
            起点不算经过；终点只走"停留"规则，不触发"经过"规则。
R-MOVE-004  主动选择停下（自家 / 与其他玩家交战）后，**本次移动剩余步数作废**。
R-MOVE-005  应战结束后，玩家停在该格，本回合不再移动。
R-MOVE-006  传送（Warp）是**位移**，不是移动：不消耗步数、不触发经过判定、
            不触发终点停留规则（除非目标格本身有可触发效果——见 R-TILE-011）。
R-MOVE-007  每回合最多进入 1 次战斗（因为停下即终止移动）。
R-MOVE-008  若启用 Move 格（§3 建议 3）：额外移动阶段上限**每回合最多追加 1 次**，防止连锁。
```

**关键：可停留格预计算（R-MOVE-003 的实现方式）**

掷骰后，在**移动开始前**就算出玩家所有可以主动停下的节点，并高亮：

```
// 输入：起点 node、剩余步数 k
// 输出：所有"可停留且可达"的节点（含到达路径）
List<Candidate> FindStopCandidates(int playerId, int node, int steps)
{
    void Dfs(int cur, int left, List<int> path)
    {
        if (left == 0) return;
        foreach (var next in OutEdges(cur))
        {
            // 可主动停留候选 = ①自己的 HomeTile ②有其他玩家的节点
            // 关键：别人的 HomeTile **不是**候选、不高亮；
            //       但骰子恰好走到时会正常触发 home 结算（两件事是两个权限）
            if (IsStoppableByPass(next, playerId))
                yield Candidate(next, path + [next], left);
            Dfs(next, left - 1, path + [next]);
        }
    }
    Dfs(node, steps, [node]);
}
```

**这个函数的存在，决定了你的网络协议长什么样：**

```csharp
// ✅ 推荐：移动命令 = 目标节点（或 null = 自由走）
public sealed record MoveCommand(int PlayerId, int? TargetNodeId) : IMatchCommand;

// ❌ 不推荐：逐格方向
// public sealed record ChooseDirectionCommand(int PlayerId, int EdgeId);
```

理由：
1. 玩家点高亮格 → 一次 RPC 说清"我要停在那儿"，服务端自己按路径重放并广播 `StepEntered` 事件。**少 4~6 次往返**。
2. 玩家想在岔路自己走而不停 → 发 `TargetNodeId = null` + 第一次岔路的 `direction`。
3. 断线重连时，"目标和路径"比一串"方向选择"更好恢复。

**UI 契约**：
- 掷骰后进入 `Moving` 状态，界面提示"选择移动方向。"
- 所有 `FindStopCandidates` 结果高亮；同时岔路节点的出边显示为可点击箭头。
- 点高亮格 = 自动按路径走过去并停下；点箭头 = 沿箭头走、不停、继续剩余步数。

### 1.6 战斗奖惩

```
R-CBT-001  战斗由珍宝 CD 自动模拟决定胜负，不存在攻/防/闪的掷骰交互。
R-CBT-002  被击倒方的碎片损失比例与胜者的胜场获得，按被击倒方的类型区分：

             类型      败者碎片损失      胜者胜场
             ----------  ----------------------------
             杂鱼      全部（100%）       +1
             玩家      50%（向下取整）     +2
             Boss      全部（100%）       +3

R-CBT-003  胜场**永不减少**。败者不损失胜场。
            （胜场 Norma 是累计阈值，可以倒扣的话，走胜场路线的玩家会在关键节点被反复打断，这是死循环。）
R-CBT-004  碎片抢夺上限：30 碎片/次（防滚雪球的安全阀）。
R-CBT-005  战败无位移：败者**留在战斗发生的地块**，不返回 home、不触发经过判定、
            不追加任何移动。
R-CBT-006  平局：双方碎片均不变，双方胜场均 +0。平局只在两种情况下产生：
             ① 同一 tick 双方同时归零；② 战斗拖到 60 秒硬上限。
R-CBT-007  战斗没有时长上限，只有超时惩罚：
             20 秒起每 0.1 秒双方各受递增的伤害（**不穿盾，被护盾吸收**），
             60 秒强制平局。因此"只叠盾、不打人、靠超时惩罚耗死对手"是合法构筑路线。
            细则见 `战斗规则书.md` BT-4.6 / BT-9。
R-CBT-008  生命值只在战斗内存在，棋盘层没有生命值；护盾也只在那场战斗内有效，
            战斗结束即消失（`战斗规则书.md` BT-4.5 / BT-4.7）。
R-CBT-009  战前准备期 5.0 秒：战斗确定发生后，双方（PvE 则只有玩家）可在
            **5 秒内再调整战斗栏**；准备期内**互不可见**对手战斗栏；
            双方都点「准备完毕」或 5 秒到 → 开战。准备期不计入战斗时长。
            细则见 `战斗规则书.md` BT-2.3.1 ~ BT-2.3.7。
            对节奏的影响：每场 PvP 平均多 2~5 秒（PvE 通常直接点掉）。
R-CBT-010  信息可见性：战斗外可随时查看**他人战斗栏的排列**（含牌名与顺序），
            但**背包内容永远不公开**。
            战斗中，双方的战斗栏可见。
            实现上必须由服务器只下发战斗栏（`PublicLoadout`），不是"下发了但 UI 不显示"。
```

### 1.7 Norma 与升级

```
R-HOME-001  「升级结算」挂在**地块**上：任意 HomeTile（不论归属）都会进行升级结算。
R-HOME-002  「主动停留权」挂在**归属**上：只有自己的 HomeTile 是可主动停留候选，
            经过时可选择停下（见 §1.4 预计算）。
            别人的 HomeTile **不是**可停留候选、不会高亮，只能靠骰子恰好走到。
R-HOME-003  升级结算内容（自家 / 别家**完全一致**）：
              ① 若满足当前 Norma 阈值 → 升级
              ② 升级后立即选择下一级的 Norma 类型（锁定，见 R-NORMA-004）
            **不恢复任何东西**——棋盘层没有生命值（`战斗规则书.md` BT-4.7）。
R-HOME-004  升级**不消耗**碎片/胜场（阈值判定）。
R-HOME-005  到达方式限定：只有「骰子正常移动的终点」能触发 home 结算。
            **Warp 传送到达不算**（R-MOVE-006：传送是位移不是移动）；
            Move 格追加的额外移动阶段算（它就是正常移动；Move 格未启用时本条不适用）。
R-HOME-006  若停下时该格有其他玩家 → 战斗与该格的 home 结算**都要执行**，顺序见 R-HOME-007。
R-HOME-007  结算顺序**写死为：先战斗，后 home 结算**。
            理由：升级判定要读**最新的**碎片/胜场，而战斗刚刚
            转移了这两样东西。必须先让战斗尘埃落定，再拿结果去查 Norma 阈值。
            结算对象**只有停留者**（走到这一格的人），与飞行员的胜负**无关**——
            战败没有位移（R-CBT-005），人还在格子上，所以照样结算。
            同格的其他玩家不是停留者，不做 home 结算。
R-HOME-008  达到 6 级 → 立即胜利，无需额外动作。

R-NORMA-001  每名玩家当前只持有 1 个 Norma：ShardNorma 或 WinsNorma。
R-NORMA-002  开局默认 ShardNorma。
R-NORMA-003  升级时选择下一个 Norma；之后在达成前**不能更改**。
R-NORMA-004  角色若有强制 Norma 类型，开局即为该类型且不可切换。
R-NORMA-005  升级判定顺序：先查 ShardNorma 再查 WinsNorma（理论上只会有一种命中，
             但如果两轨都满足，优先 Shard，保证确定性）。
```

|---|---|---|
| 1 | ≥ 15 | ≥ 1 |
| 2 | ≥ 40 | ≥ 2 |
| 3 | ≥ 80 | ≥ 4 |
| 4 | ≥ 130 | ≥ 6 |

### 1.8 经济

```
R-ECO-001  唯一货币：珍宝碎片（Shard）。全文不存在第二种货币。
R-ECO-002  碎片获得：奖励格折现、销毁珍宝、战斗抢夺、全局发放。

### 1.9 CPU 席位

> **本作没有"怪物 NPC"这种实体**：棋盘上只有两类东西——**4 个玩家席位**（真人或 CPU 填充）和**静止的杂鱼/怪物**（绑在战斗格上等人来打的遭遇物，不占回合、不移动、不进商店）。

```
R-CPU-001  CPU 通过与真人**完全相同**的 Command 接口行动：
           MoveCommand / EngageCommand / PlayCardCommand / ReorderCommand / SetNormaCommand。
           禁止"AI 直接改 GameState"的后门——否则托管局与回放会与真人局产生不同结果。
R-CPU-002  信息集相等（这是平衡的前提，也是最容易写错的一条）。CPU 能拿到的必须**恰好等于**
           一个真人能看到的（`棋盘层双栏卡槽UI与拖拽交互规格.md` §2.5）：
             自己：全部
             他人战斗栏（战斗外）：牌名 / 尺寸 / 价值 / 当前修正 / 站位顺序 / 空槽锁格
             他人背包：**只有** 占用 x/10c、张数、总价值——没有任何具体牌名
             他人（准备期 / 战斗中）：只知道"在准备"/"在交战"
           不可额外授予：对手背包里的牌、对手的随机种子、对手未公开的 Norma 切换意图。
           违规后果：AI 会"预知对手有几张防御"，胜率虚高，真人永远打不过它，而你以为是自己菜。
R-CPU-003  决策预算：单次决策 ≤ 300ms（联机托管 ≤ 100ms，超时按 R-EXC-001 走默认动作）。
           因此内核必须支持**零分配 Clone 与快速试算**（AI 做 1~2 层前瞻要靠它）。
R-CPU-004  CPU 达到 6 级 → 该 CPU 获胜，按 R-WIN-001 的普遍规则结束本局。
           不存在"NPC 赢 = 玩家失败"的第二套结算；界面只是显示"XX 先到 6 级"。
R-CPU-005  断线托管复用同一份 AI（R-EXC-002），不写第二套。
R-CPU-006  CPU 与真人权限完全相同：能进商店、能主动开战、能停自家升级，没有例外名单。
R-CPU-007  杂鱼（战斗格怪物）不是席位：不占回合、不移动、不触发商店、被打倒后该格恢复为空。
```

### 1.10 胜负

R-WIN-001  玩家先达到 6 级 → 该玩家胜利，游戏结束。
R-WIN-002  无回合上限，直到有人 6 级（单机与联机一致）。
R-WIN-003  回合顺序决定唯一性：升级只在自己的回合结算，故不存在同时达成。
```

|---|---|
| Check/Home 恢复生命 | **不存在**。home 不恢复任何东西，只做 Norma 判定 |
| 残血走棋盘 | 不存在。棋盘层永远满状态，紧张感由战斗内血量承担 |

**生命上限**是一条**战斗内参数**，由玩家等级决定（等级越高，战斗内血越厚）：

| 等级 | 1 | 2 | 3 | 4 | 5 | 6 |
|---|---|---|---|---|---|---|
| 战斗内生命上限 | 100 | 150 | 200 | 250 | 300 | — |

> 这张表只被战斗层的 `BattleConfig` 读取。棋盘层的状态结构体里**不存在** `_hp` 字段——不是"不用"，是没有。这样"残血补给""复活药""战斗前先回血"这一整类系统就不可能偷偷长回来。

### 2.3 胜场阈值

**阈值：`1 / 2 / 4 / 6 / 8`，累计 21 场。**

推导：碎片路线累计需要 Σ(15+40+80+130+210) = 475 碎片。按每完整轮 ≈ 14 格移动、每圈可得 ≈ 60 碎片估算，一局约 8 圈（≈72 回合，25~35 分钟）。胜场路线要在同样的 8 圈内达成，而 8 圈内能主动发起的战斗约每圈 1 次（怪物格 3~4 个 + 玩家相遇），故总阈值应落在 8~10 场。PvP 另有 5 秒准备期（R-CBT-009），但胜场路线的主力是打杂鱼，估算不变。

**这个数字必须用 BalanceSim 验证，它是第一个要跑的数值实验。**

**另一处必须复算**：任意 home 都能结算，一圈有 **4 个**升级兑现点，"攒够了却要跑回家"的等待成本基本消失，升级会来得更早更顺。

- 建议阈值先按**上调 15%** 起测：`17 / 46 / 92 / 150 / 240`。
- 在 BalanceSim 里做成开关 `HomeUpgradeAllOwners = true/false`，两种都跑，比较：平均对局轮数、碎片"囤积浪费量"（达到阈值后到兑现之间累计的碎片溢出）、4 名玩家的升级时间点方差（任意 home 可升级时方差应显著变小）。
- **这一条同时决定胜场路线要不要跟着调**：4 个兑现点意味着胜场路线的兑现速度也变快，两条轨道仍要对齐。

### 2.4 背包上限

背包容量 = 10 `c`（R-ECO-006）。

### 2.5 商店

| 项 | 建议值 | 备注 |
|---|---|---|
| 上架数量 | 3 | |
| 价格 | 1c/2c/3c = 2/4/8 碎片  |
| 刷新 | 每次停留 1 次，2 碎片 | |

### 关于"要不要让 CPU 看起来像人"

规则层面没有剩余工作，但有一件事值得单独想：**AI 如果每次都精确计算，玩家会觉得被读心**。建议给 AI 加一层"人格扰动"——同一份内核、同一信息集，只在评分权重上随机加减（激进 / 保守 / 理财 / 狩猎 四种人格），人格存进对局数据而不是写死在 AI 里。这样三个 CPU 会互不相同，而规则书一个字都不用改。属于 §7 B7 的范围。

## 3. UI 硬性约定

| # | 项 | 做法 |
|---|---|---|
| 1 | 顶部单行文字气泡（"你的回合。"/"选择移动方向。"/"要在 HOME 格停下来吗？"/"想要发起战斗？"） | 做一个**统一的 `PromptBubble`**：一行文字 + 可选 YES/NO。所有中断都用它。**不要做 4 种不同样式的弹窗** |
| 2 | YES/NO 两个巨型圆形按钮，分列左右 | 统一 `BinaryChoicePopup`。所有二选一（停下/开战/进传送）共用。键位固定（A/D 或 左/右） |
| 3 | 地图正中央的轮次计数器 | 需要一个等价的"当前轮次"显示，供玩家判断节奏（**不是失败倒计时**——两种模式都没有回合上限） |
| 4 | 战斗结算页：`VICTORY!` / `KO...` + 碎片 ±N、胜场 ±N + 双方 HP/ATK/DEF/EVD 战前战后对比 | 结算页必须显示：**碎片 ±N、胜场 ±N、双方等级**，以及"是否达成 Norma"。**HP 只在战斗界面里出现**（棋盘层无生命值），结算页保留"剩余生命"作为战况复盘 |
| 5 | 玩家信息卡：等级「点亮星星」、`HP 5/5`、`Stars 34`、`Wins 3`、手牌缩略 | 四角信息卡包含：**等级（点亮）· 当前 Norma 类型高亮 · 碎片 · 胜场**。⚠️ **不要在地图 HUD 上显示 HP**——棋盘层没有生命值，显示了会让玩家以为残血会影响下一步 |

> **底部卡槽带**：底部是**双排卡槽常驻带**（上排背包 10c / 下排战斗栏 4~10c）+ 自由拖拽 + **拖进专用出售区即卖** + 悬停看效果。布局尺寸、拖拽状态机、出售入口、联机权威重排全部在 `棋盘层双栏卡槽UI与拖拽交互规格.md`，本文不再重复。常驻带会让棋盘可视面积减少 14%~25%，这是该规格书 §2.4 三档收放存在的唯一原因。



**对地图设计的两条硬约束**（由 C 方案直接决定）：

1. 4 个 home 应把环**四等分**（N=32 → 节点 0/8/16/24）。因为 home 现在是可以互相替代的升级点，均匀分布能把"离最近 home 的最远距离"压到最小，避免出现"半圈没有升级点"的死区。
2. home 位置**决定玩家节奏**：出生在 home 上 ⇒ 每圈一次的稳定兑现节奏是相同的；不要出现"某个 home 前面是连续 3 个 Warp 格"之类导致兑现率异常的布局。
3. **C 方案的隐含好处（不需要补偿数值的原因之一）**：落后玩家不会因为离家太远而卡在"攒够了却兑不了"，追赶更顺。这是"任意 home 可升级"这条规则的真正价值。

## 4. 实现顺序

| 步骤 | 内容 | 验收 |
|---|---|---|
| B1 | Pcg32 + 1D6 + 有向图加载 + 校验器 | 100k 次骰子分布；5 张坏图被拒 |
| B2 | 单环移动（无交互）+ TurnLog | 走 6 步落点正确；起点不算经过 |
| B3 | **可停留格预计算** + 岔路 + `MoveCommand(TargetNodeId)` | 给定图和骰点，候选集合与手算一致；点目标格后路径重放一致 |
| B4 | 地块效果分发（全部 **9 种**，含 Boss 演化） | 每种地块一个单测；Boss 演化只在"首名到 4 级"触发一次 |
| B5 | Norma + home 结算（任意 home 可升级 / 仅自家可主动停留）+ 6 级胜利 | 阈值判定不扣碎片；别家恰好到达可升级但不可主动停留；Warp 到 home 不结算；Norma 锁定不可改 |
| B6 | 经济 + 商店 + 战斗奖惩（含分类型） | 杂鱼/玩家/Boss 三种奖惩正确；胜场不为负；平局 |
| B7 | 4 个 CPU 席位跑 500 局（AI 人格 + 收敛测试） | 500 局全部自然结束（无死局、无双方僵持）；中位圈数落在 6~8；输出胜率/轮数/碎片曲线 CSV |
| B8 | 事件流 + PromptBubble/BinaryChoicePopup | 人眼能看懂一整局 |

**B3（可停留格预计算）是前置必做项**：它决定移动协议和 UI 的形状，晚做等于重写。

## 附录 A：核心单测清单

| 测试 | 断言 |
|---|---|
| 骰子分布 | 1D6 × 100k，各面 16.67% ± 1% |
| 地图校验 | 断边/不可达/无 home/传送未配对 → 全部拒绝 |
| 起点不算经过 | 回合开始时站在自家，不触发升级结算 |
| 终点优先 | 终点格同时有玩家与自己 home → 只走停留规则 |
| 可停留格预计算 | 3 岔图 + 骰 5，候选集合与手算一致 |
| 停下作废 | 主动停下后剩余步数丢失，回合不再移动 |
| Warp 不耗步 | 传送到配对格后，步数计数不变 |
| Boss 演化 | 首名到 4 级时**所有怪物格**演化为 Boss 格；Boss 被击败后全部恢复为怪物格 |
| Norma 不消耗 | 碎片 100 达阈值升级后碎片仍为 100 |
| Norma 锁定 | 达成前切换请求被拒绝 |
| 别家不可主动停留 | 骰程内可达别人的 home，`FindStopCandidates` **不**返回它 |
| 别家恰好到达可升级 | 骰子恰好落在别人 home → 触发升级结算 |
| Warp 到 home 不升级 | 传送到自己/别人的 home → 不触发 home 结算 |
| 主动停留自家 | 自己的 home 在骰程内 → 出现在候选中，选中后升级 |
| 战斗与升级顺序 | 停在有玩家的别家 home 并战败 → **留在该格**，仍执行 home 结算（按战后最新碎片判定） |
| 停在自家但有人 | 自己的 home 上有其他玩家 → 出现候选；选中后先战斗，胜负都结算升级 |
| 战斗奖惩 | 杂鱼 100%/+1、玩家 50%/+2、Boss 100%/+3 |
| 胜场不为负 | 0 胜场时战败仍为 0 |
| 平局 | 双方碎片胜场均不变 |
| 战败不位移 | 战败后位置与战前完全相同，不触发经过判定、不触发额外战斗 |
| 每回合 1 次战斗 | 连续两次停留请求被拒 |
| 每回合 1 次发动 | 第 2 张发动型珍宝被拒 |
| 500 局收敛 | 4 席全 CPU，500 局全部自然结束（无死局）；中位圈数 6~8 |
| CPU 信息集（反例） | 对手背包里有 3 张防御时，AI 的评分输入中**不出现**这些牌名（可断言） |
| CPU 信息集（正例） | 对手战斗栏的牌名/顺序/修正对 AI **可见**（否则 AI 比真人弱，平衡测试作废） |
| CPU 命令受限 | AI 尝试直接改状态（非法 API）编译期就不可达；AI 只能经 Command 提交 |
| 存档一致性 | Save→Load 后状态哈希一致 |
| 确定性 | 同 seed 同命令流 → 事件流 SHA256 一致 |
