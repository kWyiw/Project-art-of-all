# 《Project-art-of-all》策划案写作教练

> **用途**：教策划把现在的 `README.md` ＋ `卡牌.txt` 从“提案”写成“可开工的策划案”。
> **结论先说**：现在的 README 回答了“我想做什么”，还没有回答“玩家每一回合具体做什么、程序怎么判定、四个人怎么同时玩、输了以后发生什么”。
> **用法**：不要一次写完。按下面的 5 轮走，每轮只产出该轮的东西，过门再进下一轮。

---

## 0. 先给现状做体检

### 0.1 已经能用的部分

- **主题钩子很强**：人类艺术馆、消失的名画、圆环走廊、里画廊、名画碎片——不是普通换皮大富翁。
- **玩法骨架清楚**：4 人、掷骰、环形棋盘、地块、卡组构筑、自动战斗、6 级终局。
- **地块类型有雏形**：基础 / 奖励 / 怪物 / 商店 / 传送 / home / 玩家遭遇。
- **卡牌记号有潜力**：`1c 3s 武器 1g` = 1 卡槽 / 3 秒冷却 / 词条 / 售价；`1D6` = 掷 1 枚六面骰。
- **美术方向明确**：平面立绘 ＋ 双面亚克力立牌，适合做统一角色表现。

### 0.2 现在不能开工的断点

| 断点 | 为什么现在不能写下去 | 先补什么 |
|---|---|---|
| 战斗段落截断 | README 停在「战斗中有」 | 先补完整战斗规则：HP / 护盾 / 冷却 / 目标 / 站位 / 胜负 |
| 胜负条件矛盾 | 一处说「率先升到 6 级获胜」，一处说「最高级后可选择结束游戏」 | 明确：6 级是立即胜，还是解锁“终局宣告”后才能结束 |
| 回合与多人 | 4 人轮流走棋盘，但战斗是自动战斗；其他人战斗中做什么没写 | 定义“棋盘回合”和“战斗回合”两层状态机 |
| `cost` 定义不清 | 逃跑扣 cost、商店用下次战斗 cost 买卡、战斗里又提到 cost | 只能有一个定义：战斗资源 / 货币 / 预算，三选一 |
| 卡槽关系不清 | 10 个背包槽，4/6/8/10 个战斗槽；何时切换、是否重复占槽没写 | 定义背包与出战槽的装载、替换、升级时机 |
| 词条没有交互表 | 「词条是卡牌之间交互的纽带」，但目前只有标签名 | 给武器 / 废料 / 技艺 / 陷阱 / 地产 / 资源建交互矩阵 |
| 怪物移动没规则 | 「怪物和玩家遵循一样的移动逻辑」但没有方向、刷新、碰撞、战斗规则 | 定义怪物每回合怎么走、遇到玩家/怪物/地块怎么处理 |
| 经济没有来源/消耗表 | 金币、卡牌售价、商店、升级、PvP 抢夺互相没有闭环 | 做一张金币与卡牌的价值表，算一遍 10 回合收支 |
| 棋盘没有规格 | 圆环多大、多少格、地块比例、出生点、传送门位置都没定 | 先画一张可玩的 40~60 格棋盘草图 |
| PvP 资源流动未定 | 只写“抢金币和 1 胜场”，卡牌、血量、位置、终局怎么变没写 | 明确攻方/守方、拒绝、逃跑、观战、结算 |
| 传送与里画廊不清 | 传送门持续多久、名画碎片能带几张、战斗/事件怎么用没写 | 定义刷新周期、碎片槽、一次性/永久效果 |
| 内容量不足 | 目前只有 7 张样例卡（含 1 张资源牌），没有目标数量、稀有度、卡池结构 | 先定 v1 目标：多少卡、多少道具、多少怪、多少事件 |

### 0.3 现有卡牌样例暴露的口径问题

- `汽车门板 3c 9s 废料` 没写售价；按「3c 牌 4g」应补 `4g`。
- `雨水净化器 2c 地产` 没写冷却和售价；如果是棋盘被动，应写 `—` 或 `被动`，不要留空。
- `淡水 1c 资源 0g` 是资源牌，但它占不占背包槽、能不能在战斗槽里出现、能不能被“双持”影响，都要写。
- `3D20 护盾`（均值 31.5）对 `1D6 伤害`（均值 3.5）明显不是一个量级；先定一场战斗的 HP / 护盾 / DPS 预算，再写单卡。
- `核废水` 的「1D4 中毒」：中毒层数是否叠加、每秒跳一次还是每 6 秒跳一次、是否衰减、能否致死、是否无视护盾，必须写清。
- `双持` 的「多重释放 1」：是冷却内多打一次、多打一段，还是复制一张？持续多久？能否叠加？是否影响自己？右侧相邻是否循环？
- `铁丝网` 的「2 回合」：是目标 2 次行动、2 个完整轮次，还是 2 秒？对怪物和玩家是否都生效？陷阱是否可被看见/拆除？
- `雨水净化器` 的「每回合结束生成 1 张淡水」：是棋盘回合还是战斗回合？淡水进背包还是手牌？背包满了怎么办？

## 1. 五轮写作流程

### 第 0 轮：一页纸（先别写世界观）

**产出**：一页纸 ＋ 4 条设计支柱。

一页纸必须填：

| 项 | 内容 |
|---|---|
| 一句话 | 4 人在艺术馆环形棋盘上掷骰、构筑卡组、自动战斗，先完成 6 级终局的人带走馆藏 |
| 类型 | 多人回合制棋盘策略 ＋ 牌组构筑 ＋ 自动战斗 |
| 平台 / 人数 | PC / 主机 / 移动？4 人联机 ＋ 人机补位？ |
| 单局时长 | 30 / 45 / 60 分钟？ |
| 核心资源 | 金币、战斗 cost、卡牌、背包槽、战斗槽、胜场、等级 |
| 核心玩点 | 棋盘上的路线与地块控制；战斗前的卡组布置；四个人互相抢节奏 |
| 终局 | 【待拍板】6 级是立即获胜，还是 6 级后回自己的 home 触发特殊结局？两者不能同时成立 |

设计支柱候选（选 3~5 条，每条写“宁可 A 也不 B”）：

1. **艺术史不是皮肤，是规则来源**：每张名画碎片/事件都要改变玩法，不能只换卡图。
2. **棋盘是第二副牌**：地块改造、传送、陷阱和路线选择和战斗卡组一样重要。
3. **自动战斗靠布置，不靠手速**：玩家战前决定卡槽顺序/相邻关系，战斗中看推演。
4. **四个人互相算计**：PvP、抢胜场、抢终局节奏是核心，不是附加模式。
5. **一局要有明确的追赶与反超**：领先者不能靠滚雪球直接锁死。

**过门标准**：一个没看过 README 的人，读完这一页能说出“这游戏每回合干什么、怎么赢”。

### 规则句的八个槽位（每一轮都按这个检查）

一句能交给程序执行的规则，至少要能回答：

`谁` → `在什么时机` → `对谁` → `做什么` → `数值/骰子` → `按什么顺序结算` → `上限/例外` → `玩家看到什么`

以 README 的怪物格为例：

> 坏：走到怪物地块会触发应战/逃跑，逃跑会随机没收玩家的一定卡牌，扣除一定生命值和 cost。

> 好（数值只是示范，必须拍板）：玩家 **停留** 在怪物格时，弹出「应战 / 逃跑」；选「逃跑」→ 随机弃掉背包中 **1 张** 非初始卡（背包为空则不弃）→ 失去 **当前生命 10%**（向上取整）→ 失去 **2 金币** → **不进入战斗** → 结束本回合。选「应战」→ 进入战斗，胜负结算见 §3.5。

差别不在文笔，而在程序、UI、QA 能不能各自照做。凡是出现“一定”“随机”“适当”“若干”，都必须替换成范围、公式或表格。

### 第 1 轮：把规则闭环写出来

这一轮只写三张循环图，不写内容表：

1. **棋盘回合**：回合开始 → 掷骰 → 移动 → 落点结算 → 是否战斗/购物/升级 → 回合结束 → 下一位。
2. **战斗回合**：进入战斗 → 装载/确认卡组 → 自动战斗 tick → 冷却/技能结算 → 一方归零 → 结算奖励/惩罚 → 回棋盘。
3. **经济循环**：金币来源（经过起点/奖励地块/战斗/PvP/卖卡）→ 金币去向（买卡/买道具/升级/传送/治疗）→ 卡牌来源与消耗 → 胜负节奏。

**必须回答**：

- 一“回合”是单个玩家行动，还是四个人各行动一次算一轮？
- 战斗发生时，其他玩家是等待、观战、还是同时做别的事？
- 战斗是固定时长、固定 tick，还是打到一方死亡？
- 自动战斗的“自动”到什么程度：玩家只能战前布置，还是战斗中能放道具/改目标？
- 战斗结束后，玩家回到棋盘哪个位置？回合是否继续？是否还能行动？
- 战斗中逃跑/失败，扣什么、扣多少、是否结束回合？

**过门标准**：程序能照这三张图写出一个可跑的灰盒状态机，不需要再问“然后呢”。

### 第 2 轮：系统分册

每个系统单独一节，按「定义 → 数据表 → 触发时机 → 顺序 → 上限/例外 → 表现 → 实现落点」写。建议目录：

- `3.1 棋盘与回合`：环形格数、方向、出生点、home、经过/停留、轮次、先手。
- `3.2 地块`：基础/奖励/怪物/商店/传送/home/PvP，每类的触发、刷新、可改造性。
- `3.3 等级与终局`：1~6 级成本、金币/胜场两条线、home 升级、6 级后结束方式。
- `3.4 卡牌`：卡槽 c、冷却 s、词条、售价 g、背包/战斗槽、升级、出售。
- `3.5 战斗`：HP/护盾/中毒/伤害/骰子/目标/站位/相邻/多重释放/胜负。
- `3.6 道具`：一般/特殊、使用次数、目标、战斗/棋盘使用时机。
- `3.7 经济`：金币、cost、卡牌价值、商店价格、PvP 抢夺、反超机制。
- `3.8 怪物与 PvP`：移动、刷新、遭遇、应战/逃跑、玩家遭遇战。
- `3.9 传送与里画廊`：传送门刷新、名画碎片获取/携带/使用。
- `3.10 多人/联机`：房间、回合计时、断线重连、AI 补位、观战、RNG 同步。

### 第 3 轮：内容清单

先定 v1 目标数量，再逐项建表。不要先写 100 张卡再想系统。

建议 v1 规模（可改）：

| 内容 | v1 目标 |
|---|---|
| 卡牌 | 40~60 张（含 7 张现有样例） |
| 道具 | 12~20 个 |
| 地块 | 8~12 种 |
| 怪物 | 12~20 只 / 6~10 组 |
| 事件/名画碎片 | 12~20 个 |
| 地图 | 1 张完整环形图（后续扩展） |
| 角色 | 2~4 个 |

### 第 4 轮：界面与流程

必须写清玩家从打开游戏到结束的每一次跳转：

```
主界面 → 联机房间/选人 → 棋盘 → 地块结算/商店/里画廊 → 战斗 → 战斗结算 → 回棋盘 → 6 级终局 → 结算
```

每个界面写：进入条件、退出/返回、层级遮挡、状态保留、存档/断线恢复、输入方式、动效。详见第 5 节模板。

### 第 5 轮：任务与验收

把设计拆成“一个人一天到三天能做完”的任务。每条任务必须有依据、验收标准、负责人、状态；详见第 6 节。

### 带练安排：3 次 45 分钟

不要开“把策划案写完”的大会，按下面三次过门：

| 次数 | 会前产出 | 会上只做 | 散会标准 |
|---|---|---|---|
| 第 1 次 | 一页纸初稿 ＋ 14 个拍板问题的答案草案 | 逐条拍板第 3 节；冲突项当场二选一；未定项指定负责人和截止日 | 一页纸定稿；6 级胜负、回合定义、cost 定义不再有第二种解释 |
| 第 2 次 | 三张循环图 ＋ 棋盘回合/战斗回合状态机 | 用一张真实卡牌走一遍完整回合；用一场真实战斗走一遍结算；专挑“然后呢” | 程序和策划能对着图复述同一流程；所有“视情况”被改成分支 |
| 第 3 次 | 系统分册 ＋ v1 内容清单 ＋ 界面跳转表 | 按第 8 节清单逐项验收；把不通过项拆成任务 | 每条任务有依据、验收标准、负责人；可以排期开工 |

带练时的三条硬规矩：

1. **先问“玩家此刻看到什么、能点什么”，再问设定。** 设定解释不了操作，就还不是策划案。
2. **每次只允许一个权威出处。** 同一规则在 README、表格、UI 文档里重复时，指定其中一处为权威，其余只放链接。
3. **不接受“后面再定”但没有负责人。** 未定项可以存在，但必须写 `⏳ 待定｜负责人｜截止日｜默认值`。

## 3. 必须现在拍板的 14 个问题

下表不是替你定案，而是告诉你“不拍板就写不下去”。每条的「建议默认」只是让第一版能跑，之后可以改。

| # | 问题 | 建议默认（可改） | 不定的后果 |
|---|---|---|---|
| 1 | 6 级是立即胜，还是终局宣告？ | 6 级解锁“终局宣告”；回自己 home = 特殊结局，在其他地块 = 普通结局；第一个完成者胜 | 胜负条件互相矛盾，程序和玩家都不知道什么时候停 |
| 2 | 一回合怎么定义？ | 单个玩家行动 = 1 回合；4 人各行动一次 = 1 轮；金币/传送门/怪物按“轮”结算 | 金币、传送、怪物移动全部没有时间基准 |
| 3 | 战斗是自动播片还是可操作？ | v1 自动战斗：战前布置 10 个战斗槽，战斗中只可加速/查看；不做战斗中手动放技能 | 无法确定 UI 和联机等待逻辑 |
| 4 | 其他玩家战斗中做什么？ | 其他玩家观战；战斗最长 60 秒；超时按剩余 HP 百分比判 | 4 人联机时其余三人会卡住 |
| 5 | `cost` 是什么？ | 只保留一种：战斗内的能量预算；商店不用 cost，改用金币；逃跑扣“下次战斗初始 cost” | 同一个词在三处含义不同，经济无法平衡 |
| 6 | 背包槽和战斗槽怎么切换？ | 背包 10 槽存全部卡；战前从背包选 4/6/8/10 张进战斗槽；战斗槽按顺序/相邻生效；战斗中途不可换 | “双持”“相邻”无法判定，卡牌价值失真 |
| 7 | 词条之间怎么交互？ | 先做 6 个词条的最小矩阵：武器吃“多重释放/强化”，废料吃“护盾/毒”，技艺改相邻，陷阱属地块，地产产资源，资源可卖 | 卡牌只是一堆独立效果，构筑不成立 |
| 8 | 怪物怎么移动？ | 怪物每轮沿环移动 1 格；不触发普通地块；与玩家同格触发战斗；死亡后固定点刷新；怪物之间不战斗 | 怪物地块无法预测，玩家无法规划 |
| 9 | PvP 是否强制？ | 攻方经过守方地块可选择挑战；守方可应战或逃跑（扣金币 + 结束本回合）；胜者抢金币 + 1 胜场；v1 不抢卡 | PvP 资源流动和回合顺序不清 |
| 10 | 商店何时访问？ | 只在商店地块访问；每次进入刷新 5 张卡 + 3 个道具；可卖卡；离开后库存保留到下次进入 | 随时访问会让地块失去意义 |
| 11 | 传送/里画廊持续多久？ | 传送门每 3 轮换位；进入后 3 选 1 名画碎片；碎片占 1 个碎片槽，最多带 2 张，用完即弃 | 碎片会无限囤积，终局失控 |
| 12 | 金币怎么发、怎么防滚雪球？ | 每轮开始所有人 +2 金币；领先者（等级/胜场最高）少拿 1；PvP 抢夺上限 = 目标当前金币 30% | 领先者越滚越大，后位没有反超 |
| 13 | 棋盘多大？ | v1 做 48 格环形：4 个 home、6 个基础、8 个奖励、8 个怪物、4 个商店、4 个传送、其余事件/空位；先画图再写表 | 地块比例、移动期望、单局时长都算不出来 |
| 14 | 联机怎么做？ | v1 房间制 4 人，房主权威；固定 RNG 种子；断线 60 秒重连，超时 AI 托管；不做中途加入 | 多人同步、观战、重连全部无法验收 |

## 7. 可直接发给 AI 的提示词

你是《Project-art-of-all》的主策划、系统设计师和技术文档作者。现有材料只有 `README.md` 和 `卡牌.txt`；它们是提案和样例，不是可开工的策划案。

请按以下顺序工作，**不要一次写完整本**：

**第一轮：体检与一页纸**
1. 用 10 行复述：主题、类型、人数、单局时长、核心循环、胜负、资源、内容规模、最大风险。
2. 列出 README 里所有矛盾、断点、未定义术语（尤其 `cost`、6 级胜负、战斗截断、卡槽、词条、怪物移动、PvP）。
3. 产出 1 页纸（表格）和 3~5 条设计支柱；每条支柱写“宁可 A 也不 B”。
4. 只问不超过 5 个阻塞问题；其余用【假设】并在末尾列出。

**第二轮：规则闭环**
1. 画三张循环图：棋盘回合、战斗回合、经济循环。
2. 写清一回合/一轮/一场战斗的时间基准。
3. 写清 6 级终局、home 升级、特殊结局、普通结局的判定顺序。
4. 写清战斗是自动 tick 还是可操作；其他人战斗中做什么；超时/逃跑/失败怎么结算。
5. 产出程序能照写的状态机，不要写“视情况”。

**第三轮：系统分册**
按「定义 → 数据表 → 触发时机 → 顺序 → 上限/例外 → 表现 → 实现落点」写：
棋盘与回合、地块、等级与终局、卡牌、战斗、道具、经济、怪物与 PvP、传送与里画廊、多人/联机。
每个系统必须回答：谁触发、什么时候触发、对谁生效、数值多少、能否叠加、失败/超时怎么办。

**第四轮：内容清单**
先给 v1 目标数量，再逐项建表：
卡牌（id/名称/c/s/词条/g/效果/数值/目标/来源/升级/状态）、道具、地块、怪物、事件/名画碎片、地图、角色。
每张卡必须有 c/s/词条/g；每个地块必须有触发/刷新/改造规则；每个怪物必须有 HP/行动循环/移动/奖励。

**第五轮：界面与任务**
1. 写主流程：主界面 → 房间/选人 → 棋盘 → 地块/商店/里画廊 → 战斗 → 结算 → 回棋盘 → 终局。
2. 每个界面写进入条件、退出/返回、层级遮挡、状态保留、断线恢复、输入、动效。
3. 任务表列为「任务｜依据｜验收标准｜负责人｜状态」；每条必须有依据和可测试的验收。
4. 未定项集中列，写清“谁来定/何时定/默认值”。

写作规则：
- 不写宣传语；不写官方 combo；不把未定数值写成已定。
- 数值以可执行的表和公式为准；骰子写期望值，经济写 10 回合收支。
- 同一概念只用一个词；`cost` 只能有一个定义。
- 每次修改同步版本、日期、相关表格和变更记录。

先复述理解，只问阻塞问题，然后从第一轮开始。
