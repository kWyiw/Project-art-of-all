# 本地工具与验证

改完代码至少跑「快速回路」；改到场景、预制体、Editor 脚本或序列化字段时，再加跑一次「真实 Unity 编译」。

## 一、快速回路（不启动 Unity，秒级）

```bash
dotnet build _tmp/uicheck/uicheck.csproj -c Release      # 编译 Assets/Scripts（带 UnityEngine 桩）
dotnet build _tmp/editorcheck/editorcheck.csproj -c Release  # 编译 Assets/Editor
dotnet run --project Tests/Game.Core.Checks -c Release   # 内核语义检查
```

基线：前两条 0 警告 0 错误；第三条以 `Game.Core checks passed.` 结尾，内含棋盘图（`[scene] junctions=…`）、CPU 对局、随机数、首步逆时针、战斗时间轴与回放一致性等断言。

## 二、真实 Unity 编译（批处理，约 1 分钟）

`unity` CLI 已装在 `C:\Users\shh\AppData\Local\Unity\bin\unity.exe`（0.1.0-beta.8；安装时已写入用户 PATH，新开终端可直接用 `unity`）。

```bash
cd "D:/unity hub/Project-art-of-all"
unity run . --timeout 360
```

- 成功：日志最后是 `Exiting batchmode successfully now!`，退出码 0。
- 失败：`Aborting batchmode due to failure: Scripts have compiler errors.`，退出码 1。
- 编译错误在 `%LOCALAPPDATA%\Unity\Editor\Editor.log`，形如
  `Assets\__CompileProbe.cs(5,9): error CS0103: The name 'ThisDoesNotExist' does not exist in the current context`。
- 只写 `Library/`（已忽略），不改仓库文件；第一次运行会导入资源，之后快得多。

## 三、离线渲染 UI 预览（看不见画面时用）

编辑器关掉时，可以把只有代码的界面单独渲成 PNG 检查版式：

```bash
"/d/unity hub/2022.3.62f2c1/Editor/Unity.exe" -batchmode -quit -projectPath . \
  -executeMethod CombatMeterPreview.RenderBatch -logFile _tmp/combat_preview.log
```

- `Assets/Editor/CombatMeterPreview.cs` → `_tmp/combat_meter_preview.png`：用真实 `CombatSimulation` 打一场，把战斗回放的血条 + 状态数字条渲出来（状态值由反射写进去）。
- `Assets/Editor/CardTooltipPreview.cs` → `_tmp/tooltip_preview*.png`：悬停卡牌详情面板。
- 脚本都在编辑器菜单里也有入口（`Tools/Preview Combat Meters`、`Tools/Preview Card Tooltip`）。
- 编辑器开着时批处理会失败（`another Unity instance is running`），先关掉再跑。

## 四、这套机器上用不了的部分

- 项目是 **Unity 2022.3.62f2c1 + Built-in 渲染管线**。`com.unity.pipeline`、`unity command`（驱动一个已打开的编辑器、`script eval`、Play Mode 截图）要求 Unity 6.0+，此处不可用。
- 没有 `com.unity.test-framework`，也没有测试 asmdef，`unity test` 跑不到用例——内核测试统一走 `Tests/Game.Core.Checks`。
- 因此「游戏内实际表现」仍需要人工在编辑器里点一遍；批处理只能保证编译与静态结构正确。
