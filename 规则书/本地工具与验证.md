# 本地工具与验证

改完代码至少跑「快速回路」；改到场景、预制体、Editor 脚本或序列化字段时，再加跑一次「真实 Unity 编译」。

## 一、快速回路（不启动 Unity，秒级）

```bash
dotnet build Tools/CompileChecks/UICompileCheck.csproj -c Release      # Assets/Scripts + Assets/Game/Core
dotnet build Tools/CompileChecks/EditorCompileCheck.csproj -c Release  # 再加上 Assets/Editor
dotnet run --project Tests/Game.Core.Checks -c Release                 # 内核语义检查
```

- 基线：前两条 0 警告 0 错误；第三条以 `Game.Core checks passed.` 结尾，内含棋盘图（`[scene] junctions=…`）、CPU 对局、随机数、首步逆时针、融合升级、背包容量、事件、陷阱、战斗时间轴与回放一致性等断言。
- 这两个工程用 `Assets/Game/Core` 的真源码 + Unity 的托管 dll 编译，**不需要 Unity 在跑**；`Tools/CompileChecks/CompileChecks.props` 里的 Unity 安装目录默认是本机路径，换机器用 `-p:UnityInstallRoot=...` 覆盖。
- 前提：项目至少被 Unity 打开过一次（`Library/ScriptAssemblies/UnityEngine.UI.dll` 是 Unity 生成的，不入库）。
- CPU 对局回归默认跑 **100 局**：`dotnet run --project Tools/MatchSim -c Release -- --brains --matches 100`。
  只有发布前做完整平衡审计时才加到 500 局，日常修复不重复跑 500 局。

## 二、真实 Unity 编译（批处理，约 1 分钟）

```powershell
# Unity 本体（Hub 安装目录）
"/d/unity hub/2022.3.62f2c1/Editor/Unity.exe" -batchmode -quit -projectPath . -logFile _tmp/compile_log.txt
```

- 成功：退出码 0，日志里有 `Exiting batchmode successfully now!`；失败：`Aborting batchmode due to failure: Scripts have compiler errors.`
- 编译错误搜日志里的 `error CS`（也可看 `%LOCALAPPDATA%\Unity\Editor\Editor.log`）。
- 只写 `Library/`（已忽略），不改仓库文件；第一次运行会导入资源，之后快得多。
- **编辑器开着时批处理必失败**（`It looks like another Unity instance is running with this project open.`）：先关掉编辑器；进程杀了之后 `Temp/UnityLockfile` 可能残留，删掉再跑。
- 另有一个 `C:\Users\shh\AppData\Local\Unity\bin\unity.exe`（`unity` CLI 包装器，`unity run . --timeout 360`）也能跑同一条编译，二选一。

## 三、离线渲染 UI 预览（看不见画面时用）

只有代码的界面可以单独渲成 PNG 检查版式：

```powershell
"/d/unity hub/2022.3.62f2c1/Editor/Unity.exe" -batchmode -quit -projectPath . `
  -executeMethod CardTooltipPreview.RenderBatch -logFile _tmp/tooltip_render_log.txt
```

| 脚本（`Assets/Editor/`） | 输出 | 内容 |
|---|---|---|
| `CardTooltipPreview` | `_tmp/tooltip_preview*.png` | 悬停卡牌详情面板（含长文/升级版/棋盘层注） |
| `CombatMeterPreview` | `_tmp/combat_meter_preview.png` | 战斗回放血条 + 状态数字条 |
| `ModalLayoutPreview` | `_tmp/modal_layout_expanded.png` / `_collapsed.png` | 局内弹窗与卡槽带的让位关系 |
| `HomeStopPreview` | `_tmp/homestop_preview.png` | 「经过自己的家」停步面板 |
| `EncounterPreview` | `_tmp/encounter_preview.png` / `_tmp/encounter_landing_preview.png` | 遭遇战面板（路过 / 正好停住） |
| `EventPreview` | `_tmp/event_preview_expedition.png` / `_drink.png` | 事件格三选一面板 |

## 五、这套机器上用不了的部分

- 项目是 **Unity 2022.3.62f2c1 + Built-in 渲染管线**。`com.unity.pipeline`、`unity command`（驱动一个已打开的编辑器、`script eval`、Play Mode 截图）要求 Unity 6.0+，此处不可用。
- 没有 `com.unity.test-framework`，也没有测试 asmdef，`unity test` 跑不到用例——内核测试统一走 `Tests/Game.Core.Checks`。
- 因此「游戏内实际表现」仍需要人工在编辑器里点一遍；批处理只能保证编译、静态结构与离线版式正确。
